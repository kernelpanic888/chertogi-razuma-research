# Быстрая проверка счётчика по требованию

## Триггер

Фразы пользователя `проверь счётчик`, `сколько просмотров` или `счётчик жив?` запускают этот протокол без повторного исследования архитектуры.

- `сколько просмотров`: только закрыто прочитать точное значение; не создавать тестовый просмотр.
- `проверь счётчик` или `счётчик жив?`: доказать контролируемый переход `N → N + 1`.

## Постоянные координаты

- Site project ID: `appgprj_6a6b0a8fa1b48191acb3d4809f46be77`
- Canonical URL: `https://chertogi-razuma-research.kernelpanic888.chatgpt.site/`
- D1 binding: `DB`
- Table: `site_counters`
- Row: `name = 'page_views'`
- Value column: `value`

## Протокол QCV-01

1. Через Sites `get_site` подтвердить текущий публичный URL и номер live-версии.
2. Через Sites `get_site_version` подтвердить commit SHA этой версии.
3. Запустить `scripts/read-page-views.sh` и сохранить точное исходное значение `N`.
4. Для проверки жизни открыть канонический URL ровно один раз как HTML-навигацию. CLI-запрос обязан содержать `Accept: text/html`; запрос с `Accept: */*` не является просмотром и передаётся обычному маршрутизатору. Во встроенном браузере проверить `document.readyState = complete`, наличие `main` и отсутствие ошибок консоли.
5. Снова запустить `scripts/read-page-views.sh` и потребовать точное значение `N + 1`. Для запроса `сколько просмотров` шаги 4-5 пропустить и вернуть значение из шага 3.
6. Прочитать HTTP-заголовок контрольного HTML-ответа. `X-Chertogi-Counter: recorded` подтверждает завершённый D1-инкремент; `unavailable` подтверждает безопасную выдачу страницы при сбое D1; отсутствие заголовка означает обход Worker.
7. Через Sites `get_site_worker_logs` при необходимости прочитать последние 10 минут. Логи являются вспомогательным сигналом и не заменяют точное чтение D1.
8. Если позднее станет доступен официальный инструмент D1 query, можно выполнить прямое контрольное чтение:

   `SELECT value FROM site_counters WHERE name = 'page_views';`

9. Если локальный ключ отсутствует и D1 query недоступен, прямо сообщить: сайт и событие проверены, точное число не прочитано. Не выводить число из логов, количества запросов или догадки.

## Критерии ответа

- `Сайт работает`: live-версия подтверждена, HTML загрузился, ошибок нет.
- `Событие счётчика работает`: контрольный путь попал под условие подсчёта и Worker завершился без ошибки.
- `Точное число подтверждено`: значение прочитано непосредственно из D1.
- Эти три статуса нельзя подменять друг другом.

## Защитные правила

- Не добавлять ссылку на read-only маршрут в публичный HTML.
- Без корректного Bearer-ключа read-only маршрут обязан отвечать `404`.
- Ключ хранить только локально с правами `0600` и как secret environment variable Sites; не добавлять его в Git, архив, паспорт или логи.
- Не менять HTML, визуал или канон ради проверки.
- Не хранить IP, cookies, user-agent, географию или fingerprint.
- Не считать favicon, ботов и перезагрузки уникальными людьми.
- Не публиковать техническую правку без отдельного согласия пользователя.

## Канонические пути счётчика

Канонический `public/index.html` остаётся единственным исходником. Сборка создаёт внутреннюю неизменённую копию `/_canonical/page.dat` и удаляет только `dist/client/index.html` из deploy-архива; поэтому `/` и `/index.html` не могут быть отданы до Worker, записывают D1 и получают внутренние байты с явным `Content-Type: text/html`. Нейтральное расширение исключает HTML-редиректы Cloudflare. Остальные страницы и ресурсы сохраняют asset-first режим и число не увеличивают.
