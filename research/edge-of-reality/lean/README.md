# ER-01 · Lean simulation kernel v0.1

Первое исполнимое ядро для «Края реальности». Lean 4.31.0-rc1, только Std и стандартная библиотека Lean; Mathlib и внешние пакеты не нужны. Автор постановки: Салкуцан Алексей Анатольевич. Лина — ИИ-ассистент, реализация и проверка.

## Что симулируется

Диагональное состояние одного кубита `ρ = diag(p/q, 1−p/q)` и условный фильтр `C = diag(1, l/d)`. Это строгая конечная модель отбора и доступности следа. В ней пока нет комплексных амплитуд, когерентности, запутанности, геометрии пространства-времени, физического горизонта или канала в прошлое. Это не симуляция Вселенной и не реализация полной P-CTC.

На стадии prepared массы равны p и q−p с общим знаменателем q. После фильтра общий знаменатель D=q*d²; ненормированные целые массы:

```
a = p*d²
b = l²*(q−p)
D = q*d²
successWeight = (a+b)/D
conditionalBranchZero = a/(a+b), только если a+b > 0
```

Дроби хранятся точно, без floating point и без деления в ядре. Нулевой вес не превращается в вероятность 0: условный выход отсутствует (`null`). Сокращение дробей не требуется для точности.

Переходы:

```
prepared → filtered → admitted → observed → returned
                    ↘ rejected (при нулевом весе)
```

Терминальные состояния неподвижны. Поэтому после завершения в trace повторяется один и тот же последний кадр; индекс запрошенного кадра и внутренний tick не тождественны.

Два режима наблюдения: `resolved` возвращает метки ветвей 0 и 1; `coarse` агрегирует их в единственную метку 0 с суммарной массой. Выбор наблюдения не меняет массы. Грубая проекция скрывает различия, не объявляя скрытое невозможным.

## Запуск

Из каталога проекта:

```sh
/Users/panic/.elan/bin/lake build
.lake/build/bin/er01 1 2 1 2 6 resolved
.lake/build/bin/er01 1 2 1 2 6 coarse
.lake/build/bin/er01 0 1 0 1 6 resolved
python3 verification/check_runtime.py
/Users/panic/.elan/bin/lake env lean -DwarningAsError=true Audit.lean
```

CLI: `er01 p q l d steps coarse|resolved`. Требования: `q,d>0`, `p≤q`, `l≤d`, `steps≤1000`, `q,d≤10000`. Неверный ввод: exit 2, сообщение в stderr, никакого результата в stdout. Валидный запуск: exit 0, одна строка JSON `ER01/1` в stdout.

## Контракт будущей оболочки

Оболочка отправляет точные целые параметры в Lean-executable и рисует полученный `trace`; вычисление переходов не дублируется в JavaScript. Указанные пределы CLI удерживают целые JSON-массы ниже 2^53; дроби передаются парой числитель/знаменатель. Десятичное представление — только отображение.

`readout` — доступное выбранному наблюдателю чтение и появляется лишь на стадиях observed/returned. `mass`, `input`, `successWeight`, `conditionalBranchZero` — диагностические данные полного симулятора, а не дополнительная информация, доступная грубому наблюдателю. Оболочка должна показывать их отдельно от внутреннего наблюдения; иначе она сама раскроет скрытые ветви.

Без округления определяется допустимость. При отсутствии условного выхода оболочка показывает «не определено», не подставляет ноль и не продолжает наблюдение. Реализация нативного CLI и сериализации проверена тестами; математические теоремы относятся к определениям в Core.lean, а не автоматически к JSON-парсеру или всей будущей оболочке.

## Проверяемые свойства

24 теоремы: отказ нормировки ровно при нулевой массе, существование выхода ровно при положительной; границы и знаменатель условной вероятности; монотонность tick; неподвижность терминалов; сохранение масс после фильтра; отказ/допуск по весу; завершение за четыре перехода; различимость разрешающего и неинъективность грубого чтения; сохранение суммарной наблюдаемой массы; зависимость грубого чтения только от суммы; положительный общий знаменатель; фильтр не создаёт массу; валидность всех достижимых состояний и существование posterior при достижимом наблюдении.

Аудит `#print axioms`: допускаются только стандартные `propext`, `Classical.choice`, `Quot.sound`; отсутствие пользовательских аксиом и sorryAx проверяется по полному списку. Это не утверждение «вообще без аксиом».

Файлы: `ER01/Core.lean` — модель и доказательства; `Main.lean` — CLI/JSON; `Audit.lean` — полный список проверяемых теорем; `verification/` — результаты и независимый численный oracle; `examples/` — трассы для оболочки.

## Живая визуальная оболочка

```sh
python3 visual/server.py
```

Открыть http://127.0.0.1:4186 . Локальный сервер слушает только loopback и вызывает нативный Lean-executable. Параметры интерфейса — целые проценты, знаменатели 100; переходы приходят в JSON от Lean, не вычисляются повторно в JavaScript. Доступны цикл с паузой, один переход, выбор кадра, coarse/resolved, нулевой вес и закрытая по умолчанию диагностика. Проценты и толщина линий — представление полученных масс. Сервер кэширует не более 128 трасс, ограничивает запросы и время вызова ядра. Это локальный просмотр; публичный сайт не изменён.
