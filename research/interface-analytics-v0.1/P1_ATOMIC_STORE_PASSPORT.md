# P1 ATOMIC AGGREGATE STORE PASSPORT

**Идентификатор:** `P1-AS-01`  
**Статус:** verified research candidate  
**Развёртывание:** нет  
**Публичный P0:** не изменён

## Результат

Построена эталонная семантика атомарного агрегатного хранилища. Единственная изменяющая операция принимает функцию перехода над всем `AggregateState`. Переходы сериализуются, новое состояние публикуется только после полной валидации, а исключение оставляет предыдущее состояние неизменным.

## Проверка конкуренции

- `128` одновременных допустимых событий дали итоговый счётчик `128`;
- при дневном бюджете `7` из `64` конкурентных событий ровно `7` получили `204`, а `57` получили `429`;
- итоговое сохранённое значение осталось `7`;
- потерь обновления и превышения бюджета в тесте нет.

## Проверка отказа

Синтетическая ошибка внутри транзакции откатилась полностью. Очередь после ошибки продолжила работу, следующий корректный переход был сохранён. Ошибка внешнего store преобразуется в пустой ответ `503` без состояния и диагностического текста.

## Capability fallback

Lean 4.32.1 проверил:

- `no_store_means_no_analytics`: без аксиом;
- `public_reader_survives_without_store`: без аксиом;
- `atomic_batch_is_bounded`: только `[propext]`;
- `zero_arrivals_preserve_bounded_state`: только `[propext]`.

То есть отсутствие хранилища является штатным режимом, а не падением сайта: аналитическая способность отсутствует, публичный ридер остаётся доступным.

## Минимальность данных

После события эталонное сохранённое представление имеет форму:

```json
{"schema":"p1.aggregate.v1","days":{"2026-07-31":{"page_view":1}}}
```

В storage API и состоянии отсутствуют visitor key, IP, headers, cookie, referrer и произвольное тело.

## Красная граница

`MemoryAggregateStore` доказывает семантику, но не долговечность production-хранилища. Не проверены распределённая сериализация, репликация, восстановление после сбоя процесса, provider retention и provider logs. Нельзя заменить атомарный контракт обычным read-modify-write без повторного теста.

**Следующий шаг по паспорту:** выбрать открытый persistent backend с транзакционной примитивой либо сохранить аналитику выключенной; до выбора не создавать Sites binding.
