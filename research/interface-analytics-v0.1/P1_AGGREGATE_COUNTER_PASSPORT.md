# P1 AGGREGATE COUNTER PASSPORT

**Идентификатор:** `P1-AC-01`  
**Статус:** проверенный исследовательский кандидат  
**Развёртывание:** нет  
**Публичный P0:** не изменён

## Что построено

Изолированное ядро считает четыре разрешённых события по серверному UTC-дню. Вход допускает только точный маршрут, метод `POST` и нулевой размер тела. Состояние хранит только `(day, kind, count)`, ограничено `35` днями и `140` возможными ячейками, а каждый счётчик насыщается на `2_147_483_647`.

## Проверенный контракт

```text
sanitize : PublicIngress x PrivateMetadata -> Option SafeEvent
SafeEvent := serverDay x EventKind

same PublicIngress
=> same sanitize result
=> same counter transition
```

IP, User-Agent, referrer, cookie и visitor ID представлены в формальной модели только как запрещённые метаданные. Они отсутствуют в типе `SafeEvent`, в состоянии и в выходе.

## Доказательства

### Lean 4.32.1

- `sanitize_metadata_noninterference`: не зависит от аксиом;
- `process_metadata_noninterference`: не зависит от аксиом;
- `satInc_is_bounded`: только `[propext]`;
- `pageView_record_is_bounded`: только `[propext]`;
- файл компилируется с кодом возврата `0`.

### Инвариантные тесты Node 25.9.0

`8/8 PASS`: белый список, нулевое тело, серверный день, невлияние метаданных, неизменяемость входного состояния, ограничение хранения, насыщение и запрет forged keys.

### Чёрноящичный тест `P1-AC-BLIND-01`

- синтетических запросов: `768`;
- принято по oracle: `630`;
- сохранено дней: `35`;
- найдено запрещённых маркеров: `0/10`;
- stderr кандидата: пуст;
- итог: `PASS`.

Harness не импортирует реализацию счётчика и сравнивает отдельный процесс со своим oracle. Это инженерный чёрноящичный тест, а не внешняя эмпирическая валидация.

## Чего паспорт не утверждает

Он не доказывает отсутствие IP и журналов у DNS, сети, Cloudflare/Sites, операционной системы или будущего сетевого адаптера. Он не доказывает анонимность человека и не разрешает писать «уникальные посетители». Он не означает, что статистика уже работает на публичном сайте.

## Условие допуска к развёртыванию

Нужны отдельные доказательства для сетевого адаптера: отсутствие тела и query, отсутствие чтения запрещённых заголовков, отсутствие авторских cookies, фиксированный CORS/Origin-контракт, ограничение частоты без постоянного идентификатора, отказоустойчивость, живой тест провайдерской границы и простой выключатель, возвращающий сайт к `P0`.

**Следующий шаг по паспорту:** построить адаптер как отдельный выключаемый модуль и сначала испытать его локально, не подключая к публичной странице.
