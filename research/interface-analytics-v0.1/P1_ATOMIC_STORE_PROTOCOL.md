# P1 ATOMIC AGGREGATE STORE PROTOCOL

**Идентификатор:** `P1-AS-01`  
**Статус:** implementation candidate / not deployed  
**Зависимости:** `P1-AC-01`, `P1-NA-01`  
**Публичный P0:** должен работать при полном отсутствии этой способности

## Назначение

Предоставить единственную операцию постоянного состояния: атомарный переход агрегатного счётчика. Контракт не содержит операций поиска посетителя, истории запроса или произвольного ключа.

## Интерфейс

```text
AggregateStore.transact :
  (AggregateState -> (AggregateState, Result)) -> Result
```

Переход получает проверенное агрегатное состояние, вычисляет следующее состояние и публикует его целиком или не публикует вовсе. Частичная запись запрещена.

## Сериализация

Все конкурентные переходы упорядочиваются. Если одновременно поступило `n` допустимых событий и бюджет не исчерпан, итоговый агрегат увеличивается на `n`, а не на `1`. При достижении бюджета остальные переходы получают фиксированный отказ и не меняют состояние.

## Rollback

Если функция перехода выбрасывает ошибку, новое состояние не устанавливается. Следующий переход продолжает работу с последним успешно зафиксированным состоянием.

## Capability switch

```text
store = none  => analytics capability = none
store = some  => analytics capability may be mounted
```

Отсутствие binding не является ошибкой публичной страницы. Оно означает штатный режим `P0`: аналитический маршрут не монтируется, ридер остаётся доступным.

## Сетевой ответ

Storage capability возвращает наружу только `{status, body: null, headers: {}}`. Состояние, причина внутреннего решения и величина счётчика не публикуются. Ошибка хранилища превращается в `503` без диагностического тела.

## Красная граница

In-memory реализация является проверяемой эталонной семантикой, а не постоянным production storage. Для развёртывания нужен провайдерский примитив с доказуемой сериализацией/транзакцией. Репликация, долговечность и журналы провайдера пока не доказаны.

**Следующий шаг по паспорту:** проверить конкуренцию, rollback, отказ хранилища и Lean-лемму автоматического fallback в `P0`.
