01 / PC—01

Для чего это нужноWhat this is for

Убедительный ответ ещё не даёт проверенного доказательства. Модель может ошибиться в тактике, оставить заглушку или доказать другое утверждение. Когда работа становится длинной, легко потерять и сам вопрос, и основание, на котором был принят ответ.A convincing answer is not yet a checked proof. A model can use a wrong tactic, leave a placeholder, or prove a different statement. In a long project, even the original question and the basis for acceptance can get lost.

Сопровождающий прувер удерживает связь между задачей, предложенным доказательством и проверкой. Модель предлагает шаг. Lean проверяет его в заданном контексте. Инструмент показывает зависимости и сохраняет свидетельство попытки.The proof companion keeps the task, proposed proof and verification connected. A model proposes a step. Lean checks it in the given context. The tool reports dependencies and retains an evidence record.

02 / PC—01

Одна задача. Несколько границ доверия.One task. Several trust boundaries.

Пусть Γ — доверенный контекст, P — исходное утверждение, p — кандидат доказательства. Цель проверки — установить Γ ⊢ p : P, сохранив P неизменным.Let Γ be the trusted context, P the original statement and p a candidate proof. Verification aims to establish Γ ⊢ p : P while keeping P fixed.

Γ ⊢ p : P → type check → axiom audit → evidence
Правило строгого допуска. Нужны успешная компиляция, исходный тип, полноценный аудит, отсутствие sorryAx, только разрешённые стандартные аксиомы и отсутствие предупреждений. Пустой аудит и ошибка инфраструктуры успехом не становятся.Strict acceptance. Compilation, the original type, a complete audit, no sorryAx, only permitted standard axioms, and no warnings are required. An empty audit or infrastructure error never becomes success.

06 / PC—01
Капсула Lean: четыре свойстваLean capsule: four properties
Капсула автономна: без Mathlib и внешних библиотек. Тип Fin 13 ограничивает индекс категории. Четыре теоремы проверяют отказ повторной записи, доступность свободной ячейки, отметку выбранной ячейки и сохранение остальных.The capsule is standalone: no Mathlib or external libraries. Fin 13 bounds category indices. Four theorems check rejection of repeated writes, availability of a free slot, marking the selected slot and preservation of other slots.
Scorecard.lean · Lean 4.31.0-rc1
-- PC-01: a small scorecard specification, independent of the full MG-01 engine.
-- Lean 4.31.0-rc1, no Mathlib dependency.
namespace Scorecard
structure State where
  used : Fin 13 → Bool

def record (s : State) (category : Fin 13) : Option State :=
  if s.used category then none
  else some { used := fun c => if c == category then true else s.used c }

theorem no_double_write (s : State) (category : Fin 13)
    (h : s.used category = true) : record s category = none := by
  simp [record, h]

theorem unused_is_recordable (s : State) (category : Fin 13)
    (h : s.used category = false) : (record s category).isSome = true := by
  simp [record, h]

theorem record_marks_used (s : State) (category : Fin 13) (t : State)
    (h : record s category = some t) : t.used category = true := by
  simp only [record] at h
  split at h
  · contradiction
  · cases h
    simp

theorem record_preserves_other (s : State) (category other : Fin 13)
    (t : State) (h : record s category = some t) (hne : other ≠ category) :
    t.used other = s.used other := by
  simp only [record] at h
  split at h
  · contradiction
  · cases h
    simp [hne]
end Scorecard

Что именно сказано в каждой теоремеWhat each theorem actually states
no_double_write
Если ячейка уже занята, переход возвращает none.If the slot is already used, the transition returns none.
unused_is_recordable
Если ячейка свободна, возвращается некоторое новое состояние.If the slot is free, some new state is returned.
record_marks_used
После успешной записи выбранная ячейка занята.After a successful write, the selected slot is used.
record_preserves_other
Другая ячейка сохраняет прежнее значение.Any other slot keeps its previous value.
Ни одна из этих формулировок не утверждает баланс классов, оптимальность советника или корректность произвольного внешнего приложения.None of these statements asserts class balance, advisor optimality or correctness of an arbitrary external application.

Свидетельство: что остаётся после попыткиEvidence: what an attempt leaves behind
Каждая попытка получает отдельный каталог с UUID. Следующая попытка не перезаписывает предыдущую. latest.json служит удобным указателем и меняется; архивом является сам каталог запуска.Every attempt gets a separate UUID directory. The next attempt does not overwrite the previous one. latest.json is a changing convenience pointer; the attempt directory is the archive.
runs/
  latest.json
  <timestamp>-<uuid>/
    task.json          # fixed context and theorem header
    generation.json    # prompt, mode, budget, stop reason
    raw.txt            # unmodified model output
    proof.txt          # extracted proof term
    Candidate.lean
    Expected.lean      # isolated expected-type stub
    term/
    compile/
    inspection/audit.json
    result.json
    seal.json
Сохраняются версия Lean, хеш инспектора и хеши файлов. result.json описывает решение, seal.json хеширует сам результат. Перед чтением через replay проверяется целостность.The Lean version, inspector hash and file hashes are retained. result.json describes the decision; seal.json hashes the result itself. replay checks integrity before reading it.
lean-proof-companion replay runs/<attempt-directory>
Хеши обнаруживают изменение, пока доверен сам манифест. Это не подпись, независимая аттестация или физически неизменяемое хранилище. Тот, кто может переписать весь каталог вместе с хешами, может подменить и запись. Для более сильной гарантии нужны отдельная защита и подпись архива.Hashes detect changes while the manifest itself is trusted. They are not signatures, independent attestations or physically immutable storage. Someone who can rewrite the whole directory and its hashes can also replace the record. Stronger guarantees need separate protection and archive signatures.

Где заканчивается гарантияWhere the guarantee ends
Исходный Lean-проект, контекст, импорты и плагины считаются доверенными. Извлечение задач обрабатывает исходный Lean-файл, включая его эталонные тела. Нельзя бездумно запускать его на чужом потенциально вредоносном проекте.The Lean project, context, imports and plugins are trusted inputs. Task extraction processes the source Lean file, including its reference bodies. Do not casually run it on someone else’s potentially malicious project.
Проверка кандидата и инспекция выполняются отдельными процессами с запретом сети и ограничением записи на рабочий каталог соответствующего процесса. Чтение файлов компьютера разрешено. Это ограничение не прошло независимый аудит и не является полной изоляцией вредоносного кода.Candidate checking and inspection use separate processes with network denied and writes limited to each process’s work directory. Host file reads remain allowed. This restriction has not been independently audited and is not complete isolation for hostile code.
  • Для недоверенных входов используй отдельную машину или одноразовую macOS VM без секретов.For untrusted inputs, use a dedicated machine or disposable macOS VM without secrets.
  • Версия Lean, нативная среда, инспектор и импортированные зависимости входят в основание доверия.The Lean version, native runtime, inspector and imported dependencies are part of the trust base.
  • Текущий терминальный парсер использует встроенную грамматику Lean; собственные расширения синтаксиса проекта могут быть отклонены заранее.The current term parser uses Lean’s built-in grammar; project-specific syntax extensions can be rejected early.
  • Проверка hashes не заменяет повторную компиляцию. Формальная теорема не заменяет проверку соответствия спецификации продукту.Hash verification does not replace recompilation. A formal theorem does not replace checking that the specification matches the product.
